## 摘要
基于 Transformer 模型的自回归解码（AR）在单流推理时受内存带宽限制，而这正是端侧文本转语音（TTS）的典型部署模式。Qwen3-TTS 的实时流式合成每秒需要超过 200 次串行模型调用，其中主要开销来自内层循环 MultiCodeDecoder——它需要为每 80 ms 音频帧生成 15 个残差向量量化（RVQ）码。我们为 MultiCodeDecoder 提出 RVQ 位置感知投机解码，在仅增加 5×10⁻⁴% 参数、每轮投机/验证开销为 10% 至 20% 的情况下，达到每次模型调用 2.47 个被接受的 token，将实时合成的串行模型调用次数从每秒 200 次降至 88 次。该方案在所部署的 top-k 采样下具有分布无损性，其与原系统持平的词错误率（WER）也与这一保证相符。在近期的 iPhone 与 Apple Silicon Mac 设备上，我们为 Qwen3-TTS 0.6B 的 RVQ token 生成实现了 2 至 2.2 倍的加速。

## Abstract
Autoregressive decoding (AR) with Transformer models is memory bandwidth bound at single stream inference, the typical deployment regime for on device text to speech (TTS). Real time streaming with Qwen3-TTS requires more than 200 sequential model calls per second, dominated by the inner loop MultiCodeDecoder that emits the 15 residual vector quantization (RVQ) codes per 80 ms audio frame. We propose RVQ position aware speculative decoding for the MultiCodeDecoder, attaining 2.47 accepted tokens per model call at $5\times10^{-4}$ percent added parameters and 10 to 20 percent per round speculation/verification overhead, reducing real time synthesis from 200 to 88 sequential model calls per second. The scheme is distributionally lossless under the deployed top-k sampling, and WER parity with the original system is consistent with this guarantee. We deliver 2 to 2.2x speedup for RVQ token generation with Qwen3-TTS 0.6B on recent iPhone and Apple Silicon Mac devices.

# 论文总结：RVQ Position Aware Speculative Decoding for On Device Text to Speech

## 1. 核心问题与研究背景

- **部署场景**：端侧文本转语音（TTS）在单流（single stream）推理下，Transformer 自回归解码（AR）是**内存带宽受限**而非算力受限。
- **具体瓶颈**：Qwen3-TTS 采用两层嵌套循环生成 RVQ（残差向量量化）码——
  - 外层 `CodeDecoder`（28 层）每 80 ms 音频帧调用一次，产出粗粒度码 `c0`；
  - 内层 `MultiCodeDecoder`（5 层）自回归调用 **15 次**，产出残差码 `c1…c15`。
- **量化压力**：12.5 帧/秒 × 16 码/帧 = **200 token/秒**，而每个 token 都对应一次串行模型调用，故实时合成要求 **≥200 次顺序模型调用/秒**；且由于调用过于密集，kernel launch 开销与 KV cache 管理无法被摊薄。
- **整体含义**：内层循环主导单帧延迟。投机解码（speculative decoding）是天然解法——用廉价 drafter 一次提出 k 个候选，由 target 一次并行验证，平均接受 k̄ 个即可每次调用产出 k̄+1 个 token。
- **已有工作的不足**：VADUSA、Nguyen et al. 等 Medusa 式方案针对**时间维 token 循环**，需训练数百万参数的新 draft head、采用松弛/启发式接受规则（改变输出分布）、仅报告 GPU 结果；EAGLE、ReDrafter 同样需训练额外 draft 网络；粗粒度接受、delay pattern、masked parallel generation 等则需重训 backbone。这些在移动端均带来资产体积、内存与单次计算开销的实质负担。

## 2. 方法论

### 2.1 核心思想
- 将 Medusa 框架扩展到 Qwen3-TTS 的 `MultiCodeDecoder`，利用其**天然的位置多头结构**（15 个残差码位各有独立的输入 embedding 表与 LM head），**复用冻结的原有 LM head 作为 drafter**，仅新增 3,072 个位置偏移参数，并把 drafter 与 verifier **融合进单次编译后的模型调用**。

### 2.2 关键技术细节

- **Medusa 作为自然基线**：MultiCodeDecoder 构造上就是多头的，无需改架构即可支持 Medusa 式投机；但每个 LMH 只在其自身的码位上有良好定义，直接套用会因**位置错配**导致接受率低。

- **改进一：树注意力（Tree Attention）**
  - drafter 在 K 个位置各取 top-m 候选，构成深度为 K 的树，每个根到叶路径是一条候选续写（笛卡尔积最多 m^K 条路径，但树只有 N 个不同节点）。
  - N 个候选 token 与已提交前缀打包成一条长度 q = N+1 的查询，在一次 MultiCodeDecoder 调用中验证，用稀疏树掩码使每个 token 只注意其祖先。
  - 验证采用标准投机接受规则 + 残差重采样，沿树应用。
  - 问题：增益只在大 q 时显现，而 q 增大后验证调用转为**算力受限**，侵蚀端到端加速。

- **改进二：RVQ 位置感知偏移 + 稀疏树注意力**
  - 运行时位置 k：`LMH_k` 不加偏移直接产出被接受的 token（与基线 AR 路径完全一致，**保证接受**）；`LMH_{k+j}` 接收偏移后的隐状态 `h_k + b_j`（j = 1…K，K = 3），产出第 j 个 draft。
  - K 个偏移向量 `b1…bK` 在所有起始位置 k 间**共享**。
  - 再将完整树**剪枝为稀疏路径子集**，在保持大部分接受率增益的同时把验证查询长度控制在带宽受限区间。
  - **稀疏树离线标定**：在标定集上统计逐深度、逐排名的接受率，按"对期望接受前缀长度贡献最大"贪心逐节点生长，直至节点预算 N；树深上限为 K；N 按设备分别选择。

- **偏移训练流程**
  - 冻结 backbone、各位置 embedding 表与全部 LM head，**仅训练 b1…bK（共 3,072 参数）**。
  - 用 teacher forcing 跑冻结模型（VoxPopuli 训练集），在每个内层位置 k 取隐状态 `h_k` 与后续位置的 ground-truth 码。
  - 将 `h_k + b_j` 送入冻结的 `LMH_{k+j}`，对 ground-truth 码 `c_{k+j}` 计算交叉熵损失，在 j ≤ K 与所有有效位置上求和（沿用 Medusa head 训练配方）。
  - 优化器：Adam，lr = 1e-3，batch size 32。
  - **verifier 流永不消费偏移状态**，因此部署输出分布不受影响。

## 6. 主要结论与发现

- **接受率**：每次 MultiCodeDecoder 调用接受 **2.47 个 token**（Medusa head 为 2.60，复用裸 head 仅 1.70），新增参数仅 3,072（约 +5×10⁻⁴%）。
- **系统级收益**：实时合成所需的顺序模型调用从 **200 次/秒降至约 88 次/秒**（12.5 次外层 + 约 76 次内层）；每轮投机/验证开销 10–20%。
- **实测加速**：在 iPhone 17 Pro Max 与 MacBook M3 Pro 上取得 **2.34× / 2.13×**（N = 32），iPhone 12 上 1.82×（N = 16）；整体部署加速区间为 **2–2.2×**。
- **无损性**：偏移只进入 drafter 流，verifier 输出与 AR 基线一致，因此在所部署的 top-k 采样下**分布无损**；六语种 WER 均不高于 AR 基线，且人工试听无音色、韵律或伪影差异，已在 Argmax SDK 生产环境部署且无质量回退。
- **跨语言稳健**：仅在英语数据上

训练偏移向量，但在六语种（英、德、西、俄、日、中）上均观察到一致的接受率提升与不劣于基线的 WER，说明位置偏移捕捉的是 **RVQ 码位之间的通用结构关系**（即"第 j 个残差码应如何由第 k 位隐状态预测"），而非语言特定信息，因而具备跨语言迁移能力。

## 7. 局限性与未来工作

- **方法边界**
  - 位置感知偏移的成功依赖 MultiCodeDecoder 的**位置多头结构**，即每个码位有独立的输入 embedding 与 LM head。对于不具此结构的 TTS/LLM 解码器，无法直接复用冻结 head 作为 drafter，需退回 Medusa 式新 head 方案。
  - 稀疏树形状需**按设备离线标定**（N 依设备选择），增加了部署侧的标定流程；若设备/精度组合变化（如 W4A16、其他 NPU），需重新标定。
  - 偏移向量数量 K 固定为 3，未探讨更大 K 是否能在更强带宽约束下进一步收益，也未讨论 K 与 m、N 的联合最优。
- **实验覆盖**
  - 仅报告 **p50 延迟**，缺少 p95/p99 尾部延迟、功耗与峰值内存等端侧关键指标；对实时语音场景而言，尾部延迟直接影响卡顿体验，是重要的补充方向。
  - 未做与 VADUSA、EAGLE、ReDrafter 等已有投机方案的**同条件实测对比**，加速数字虽明确但缺乏横向定位。
  - 训练数据仅英语（VoxPopuli），标定仅英语（LibriSpeech），非英语语种的接受率并非最优，若按语种微调偏移或扩大训练语种覆盖，可能进一步提升。
  - 未报告训练时长/步数与收敛曲线，偏移训练的稳定性与可复现性细节缺失。
- **可探索方向**
  - 将偏移参数按语种或说话人做轻量适配（仍保持参数量极小）；
  - 将稀疏树标定自动化并纳入 CI，形成"设备—树形状"映射表；
  - 结合 KV cache 复用/前缀共享进一步压缩验证调用开销；
  - 在更低精度（W4A8/W4A16）与更多 NPU 后端上验证带宽受限区间的位置是否漂移。

## 8. 总体评价

- **核心贡献**：论文识别出端侧 TTS 中"内层 RVQ 自回归循环"这一被忽视的带宽受限瓶颈，并提出一个**极简且无损**的解法——用 3,072 个共享位置偏移向量把冻结的 15 个位置 LM head 复用为 drafter，再配合稀疏树注意力把验证控制回带宽受限区间。方法在概念上干净，工程上可落地（已在 Argmax SDK 生产部署）。
- **方法论亮点**：
  1. **参数量与收益的极端不对称**（+5×10⁻⁴% 参数换取约 2.3× 加速），说明在结构化的多头解码器上，问题往往在于"位置错配"而非"容量不足"；
  2. **无损性有清晰论证**：偏移只进入 drafter 流，verifier 流永不消费偏移状态，故输出分布与 AR 基线一致，这比松弛接受规则类方案在质量保证上更可靠；
  3. **树形状的设备相关标定**把"加速比"从超参数问题转化为部署配置问题，实用性强。
- **待补强之处**：横向基线对比、尾部延迟与能耗指标、K/m/训练数据的消融、更严格的 WER 统计检验，以及跨精度/跨后端的泛化验证。若补齐这些，论文的说服力将从"有效"提升到"完备"。
- **适用读者**：端侧语音合成、实时推理加速、投机解码与神经音频编解码方向的工程与研究读者，尤其适合关注"在冻结模型上做最小改动"这一约束场景的实践者。
