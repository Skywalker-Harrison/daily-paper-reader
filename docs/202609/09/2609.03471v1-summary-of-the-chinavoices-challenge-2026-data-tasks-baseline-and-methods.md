## 摘要
本文总结了ChinaVoices 2026挑战赛，该挑战赛旨在为中文方言语音处理建立统一的任务定义和评估条件，并推进多方言识别和自动语音识别技术的发展。挑战赛涵盖16个方言类别，定义了两个任务：中文多方言识别和中文多方言自动语音识别（ASR）。挑战赛使用参考集、开放评估集和隐藏评估集，共计约320小时的语音数据。两个任务使用相同的评估音频，每个任务都包含受限数据和开放数据赛道。我们描述了任务设置、数据、评估指标和Qwen3-ASR-1.7B基线系统，并分析了排行榜结果和提交的系统。共有28个团队提交了结果，17个团队提供了系统报告，其中15个团队的系统通过合规性审查并被纳入分析。大多数合格系统优于基线系统，两个任务在隐藏评估集上的官方前三名排名保持不变。方言级别的结果表明，识别准确率较高的类别通常具有较低的ASR错误率，尽管这两个任务评估的是相关但不同的能力。领先的识别系统通常利用方言判别性声学表示，而领先的ASR系统则强调数据标准化、增强和辅助CTC目标。这些结果为开发和评估中文多方言语音处理系统提供了实用指导。

## Abstract
This paper summarizes the ChinaVoices Challenge 2026, which aims to establish unified task definitions and evaluation conditions for Chinese dialect speech processing and to advance multi-dialect identification and automatic speech recognition. The challenge covers 16 dialect categories and defines two tasks: Chinese Multi-Dialect Identification and Chinese Multi-Dialect Automatic Speech Recognition (ASR). It uses approximately 320 hours of speech across the Reference Set, Open Evaluation Set, and Hidden Evaluation Set. The two tasks use the same evaluation audio, and each includes restricted-data and open-data tracks. We describe the task settings, data, evaluation metrics, and Qwen3-ASR-1.7B baseline, and analyze the leaderboard results and submitted systems. In total, 28 teams submit results, 17 provide system reports, and systems from 15 teams pass the compliance review and are included in the analysis. Most eligible systems outperform the baseline, and the official top-three order remains unchanged on the Hidden Evaluation Set for both tasks. Dialect-level results show that categories with higher identification accuracy generally have lower ASR error rates, although the tasks assess related but distinct capabilities. Leading identification systems commonly exploit dialect-discriminative acoustic representations, whereas leading ASR systems emphasize data normalization, augmentation, and auxiliary CTC objectives. These results provide practical guidance for developing and evaluating Chinese multi-dialect speech processing systems.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景问题**：当前中文标准普通话 ASR 已相当成熟，但真实场景中大量中国方言（如粤语、闽南语、客家话、潮汕话等）在识别上仍面临困难。随着多方言 ASR 研究增多，学界面临的真正障碍是**缺乏统一的方言清单、训练资源、评测口径和公开可复现的评估集**——不同研究各自使用不同语料与评估条件，导致系统间结果无法客观横向比较。
- **解决路径**：ChinaVoices 2026 提供了首个覆盖 16 类中文方言的统一公开评测平台，明确任务定义、数据分割、评估度量与参赛约束，将“方言识别”（identifying the dialect category）与“方言内容转写”（accurate transcription）作为两个关联但独立的挑战任务同时推进。
- **整体含义**：该挑战赛为学术与工业界提供了可复现的中文多方言语音处理基准，并对参赛系统的拓扑结构、系统设计和方言级表现做了系统分析，为后续多方言研究提供了可靠的参考基础。

## 2. 论文提出的方法论：核心思想、关键技术细节（用文字说明）

- **任务框架**：按两个任务 + 两个数据轨道组织，形成四个排行榜：
  - `Task 1` 多方言识别（Multi-Dialect Identification）
  - `Task 2` 多方言 ASR（Multi-Dialect ASR）
  - 每种任务分别设 **关键受限数据赛道（restricted-data）** 和 **开放数据赛道（open-data）**，受限赛道决定官方排名，开放赛道仅供探索性能上限。
- **方言体系**：正式定义以下 16 类方言/口音标签：anhui、cantonese、changsha、chaoshan、dongbei、henan、kejia、minnan、nanchang、nanjing、shan1xi（山西）、shan3xi（陕西）、shandong、sichuan、wuhan、wuyu。官方评估脚本统一使用上述标签。
- **Task 1 指标**：方言识别以类别内准确率 `ACC_k = C_k / N_k × 100%` 和宏平均准确率 `ACC_macro = (1/K) Σ ACC_k (K=16)` 为官方排名指标。
- **Task 2 指标**：多方言 ASR 采用字符错误率 `CER_k = (S_k + D_k + I_k) / M_k × 100%`，以及 16 类方言上的宏平均 `CER_macro = (1/K) Σ CER_k`。宏平均保证每个方言类别在指标中权重相等，符合低资源方言公平评价的目的。
- **系统约束**：系统必须是**单一主模型/统一架构**处理全部 16 类方言，而不是串联多个独立方言专用模型；推理在离线条件下进行。
- **基线方法（关键实现）**：
  - 基于公开预测练模型 `Qwen3-ASR-1.7B`。
  - 用 `ms-swift` 做监督微调（SFT）。
  - 将方言标签预测和转写任务统一成条件生成：训练时目标序列格式化为 `language Chinese <dialect><asr_text> <text>`。
  - 解码时输出 `<dialect>` 前内容用于方言识别，`<asr_text>` 后内容用于 ASR。
  - 其中语言模型部分使用 LoRA 适配，而音频编码器和前端对齐器冻结不动。
  - 训练数据来自经批准的公共方言语料库 + 参考集的内部分割（不跨越说话人），并手工标注质量检查。
- **数据设计思路**：Reference/Open/Hidden 三组互斥（speaker-disjoint），严格禁止在训练、微调或标签生成时利用开放评估集与隐藏评估集。

## 3. 实验设计：数据集、基准、对比方法

- **数据集规模与结构**（总计约 320 小时，16 个方言）：
  - Reference Set：每方言约 3 h，提供音频 + 方言标签 + 转写文本（组织和训练阶段可用）。
  - Open Evaluation Set：每方言约 7 h，只公开音频不公开标签/文本，用于官方排行榜分数。
  - Hidden Evaluation Set：每方言约 10 h，完全不发布，仅由官方用于对前 3 名受限系统进行独立复审。
- **公共语料允许清单**（受限数据赛道）：AISHELL-1/3/4、WenetSpeech、KeSpeech、WenetSpeech-Yue、WenetSpeech-Chuan、WenetSpeech-Wu，且附有覆盖客家话、闽南语等的官方列表。
- **参赛规模**：28 个队伍提交结果，17 份系统报告；合规审查后 15 支队伍系统进入最终分析——进行整体排行榜、方言级对比、错误模式分析和系统设计分析。
- **基线与主要参赛系统对比**：
  - 基线（Qwen3-ASR-1.7B）在 Open Evaluation Set 上基线识别 ACC_macro = 53.62%，ASR CER_macro = 18.10%。
  - 受限 data 识别赛道：最好系统 scy919 达到 ACC = 83.19%（较基线绝对提升 29.57 个百分点），Optima 78.47%，zenava.ai 73.42%。
  - 受限 data ASR 赛道：TeleASR 达到 CER = 11.08%（绝对下降 7.02 个百分点，相对错误率降 38.8%），Mlslabs 11.22%，Kyoto-Tsinghua Team 11.75%。
- **重要设计——验证机制**：官方排名先看 open eval 结果，但最终名次按合规、可复现性复现及隐藏级分数复审后的结果为准：两个任务的官方前三名顺序在 Hidden Evaluation Set 上与 Open Evaluation Set 表现完全一致。

## 6. 论文的主要结论与发现

- 全部合格的识别系统中 8/8 超过基线 ACC（53.62%）；全部合格 ASR 中 9/11 超过基线 CER（18.10%），冠军在隐蔽集上仍领先，且隐藏集与官方 Open Eval 的顺序一致性得到确认，说明前 3 名系统稳定性强。
- **识别难度并不均匀**：`dongbei`、`cantonese`、`shan3xi` 的 ACC 均在 95%+，是最容易识别；然而 `kejia` 均值 ACC 只有 43.25%，是最困难类别，`shan1xi`、`nanjing`、`chaoshan`、`nanchang` 也为中等偏难。
- **混淆误差模式具有方向不对称性**：
  - `minnan → chaoshan`（19.90%）；`kejia → chaoshan`（16.93%）及 `kejia → nanchang`（19.73%）。
  - `changsha → wuhan` 比反向高得多，`nanjing → anhui` 方向差也显著，预测错误不只是相似方言间均匀混淆。
- **识别与 ASR 两者能力高度相关但非完全一致**：一般识别 ACC 高的方言、ASR CER 会较低，但存在清晰反例：`wuyu` 识别 ACC 高、CER 也偏高，`nanjing` 和 `wuhan` 则出现识别难但转写相对好的现象。
- **技术策略分层**：
  - 领先识别系统的共性环节在“方言判别性/多层声学表征 + 互补决策后段”（FireRedLID 多层级、TabPFN 后端、或 LoRA 适配的生成模型都有效）；
  - 领先 ASR 团队多集中于 FireRedASR2-AED 为底座，并配以跨语料文本归一化、语境扩展、速度扰动/噪音注入、难方言过采样、联合 CTC 对齐目标。
- **基线模型不是最终天花板**：相同 Qwen3-ASR / FireRedASR2-AED 底座间仍存在显著性能差，说明最终成绩主要由数据处理、难方言覆盖和对齐策略决定，底座决定起点和范围，不决定最终名次。

## 7. 优点
- **评测统一性高**：16 类方言共同采用了手工转写、质量检验、说话者身份不相交的三分集和宏平均指标，实现了先前缺失的标准化可复现评价。
- **任务设置综合考虑输出形式差异**：识别需要分类标签，ASR 需要考虑用户级别的替换/插入/删除错误；通过两类指标避免了单指标偏置评价。
- **受限 vs 开放轨道并行**：既保证公平可控的结果竞逐（非依赖非公开语料获得排名），又允许高资源团队探索上限，实验信息量丰富。
- **方言级分析深入**：不仅仅报告一张排名表，还分析了方言难度梯度、方言级混淆方向特征、误差成分（替换/删除/插入率），对构建低资源方言系统可落地的指导意义较高。
- **对隐私和数据集污染的约束突出**：明文规定三集说话人互斥，且严禁将 open/hidden 数据用于训练和 pseudo-labeling，极大释放了语料泄漏风险。
- **平衡稳健的结论风格**：没有过度解读开放轨道“外部数据优势”，也没有将性能差异归因到具体单一组件，而是强调完整系统的多种相互作用，体现分析中肯性。

## 8. 不足与局限

- **无法进行逐组件隔离对比**：系统是整体工程组合，无法从中推断某种数据 / 模型策略的独立增益，也无法拆出消融级可比数据。
- **开赛道实际投入有限**：Open-data 赛道只有少数队伍参投且结果不稳定——有的队伍开轨道更好而另一些反而更差，对于“外部自采/许可数据是否能带来平均收益”的问题目前不能作答。
- **隐藏评估结果的验证范围窄**：只有官方前三被复评隐藏集，对排行第 4–15 名系统的泛化能力我们无从考证；这使得较长的性能尾部分布无法判断稳健性。
- **计算资源信息缺失**：没有列明训练用的 GPU 配置、规模、运行时间、能耗等，限制了可复现的资源预估水平。
- **方言覆盖面仍有边界**：论文中只提供 16 个类别（如较难 8 种少数民族差异化的北方晋语、吴语等也相对有限，像中原官话中的细分并未完全展开），且话语场景大多属于相对干净的语音数据，离重度带噪的工业对话场景还有距离。
- **指标解释存在约束**: 由于 16 个方言下样本量较少和 HIDDEN 集合难度未标校，文中关联分析虽然明显，仍是描述性统计，严格因果/泛化推导还需要更多轮任务结果数据支撑。
